# ManyCast

**Одна программа OBS - несколько RTMP-платформ одновременно - и второй, вертикальный кадр для мобильных.**
Без сервиса рестриминга и без лишнего кодирования, когда потоки могут использовать энкодер основного эфира.

## ✨ Возможности

| | |
|---|---|
| **Несколько потоков сразу** | Можно вещать одновременно на любое число RTMP-платформ (Twitch, YouTube, TikTok, ...) из одного OBS. |
| **Без сервиса рестриминга** | Каждый поток - обычный выход со своим ключом: данные уходят только на сами платформы. |
| **Ноль лишнего кодирования** | По умолчанию потоки используют энкодер основного эфира: одна закодированная картинка мультиплексируется и отправляется несколько раз. |
| **Отдельный энкодер по требованию** | Любой поток может вместо этого использовать свой энкодер со своим битрейтом, разрешением, частотой кадров и битрейтом звука. |
| **Вертикальный кадр** | Второй кадр (1080×1920 по умолчанию) со своей сценой, живым предпросмотром и редактированием мышью - для TikTok, YouTube Shorts и любой другой цели 9:16. |
| **Независимая раскладка** | Источники общие с горизонтальной сценой, но их положение, масштаб и обрезка в вертикальном кадре независимы: двигай веб-камеру для мобильных, не трогая раскладку рабочего стола. |
| **Общий вертикальный энкодер** | Вертикальные потоки с одинаковыми настройками используют один энкодер вместо энкодера на каждую платформу. |
| **Настройки для каждого профиля** | Потоки и ключи хранятся для каждого профиля OBS; размер кадра и список вертикальных сцен - в настройках плагина. |
| **7 языков** | Английский, русский, немецкий, французский, итальянский, испанский и упрощённый китайский. |
| **Покрыт тестами** | Юнит-тесты (doctest) для кода без зависимостей от OBS, проверка согласованности локалей и смоук-тест собранной DLL. |

## 🚀 Установка

1. Скачай `manycast-windows-x64.zip` из [последнего релиза](https://github.com/Him4enko/Manycast/releases).
2. Распакуй папку `manycast` в `%ProgramData%\obs-studio\plugins` так, чтобы получилось
   `%ProgramData%\obs-studio\plugins\manycast\bin\64bit\manycast.dll`.
3. Перезапусти OBS и включи доки в `Вид → Доки → ManyCast` и `Вид → Доки → ManyCast Портрет`.

Проверить загрузку можно в `Справка → Файлы журнала → Посмотреть текущий журнал`:
`[manycast] ManyCast loaded (version 0.1.0)`.

<details>
<summary>Портативная установка (рядом с самой OBS)</summary>

```powershell
$obs = "{your-path-to-obs}\OBS Studio"
Copy-Item "<extracted>\manycast\bin\64bit\manycast.dll" "$obs\obs-plugins\64bit\" -Force
Copy-Item "<extracted>\manycast\data\locale\*.ini" "$obs\data\obs-plugins\manycast\locale\" -Force
```
Удали копию из `%ProgramData%`, чтобы OBS не загрузила плагин дважды.

</details>

## 🔨 Сборка

Проект основан на [obs-plugin-template](https://github.com/obsproject/obs-plugintemplate):
CMake скачивает исходники OBS, готовые зависимости и Qt6 в `.deps` и сам собирает
`obs-frontend-api`, поэтому первая конфигурация требует интернета и занимает время.

```powershell
# из корня репозитория
$cmake = "{your_path}\cmake.exe"

& $cmake --preset windows-x64
& $cmake --build --preset windows-x64 --config RelWithDebInfo
& $cmake --install build_x64 --config RelWithDebInfo --prefix "$env:ProgramData\obs-studio\plugins"
```

В CLion просто открой папку и выбери пресет `windows-x64` (Visual Studio) или `windows-x64-ninja`
(Ninja + MSVC-тулчейн CLion). Те же шаги выполняются на каждый push в
[`.github/workflows/build.yaml`](.github/workflows/build.yaml), который ещё и прикладывает готовый
к установке zip как артефакт.

## 🎛 Использование

### Док `ManyCast`

Открывается в `Вид → Доки → ManyCast`.

1. Нажми **Добавить поток** и заполни диалог:
   * **Режим → Сервис OBS (Twitch, YouTube, ...)** - выбери платформу и сервер из того же списка,
     что использует сама OBS, затем вставь ключ потока;
   * **Режим → Свой RTMP-сервер** - введи RTMP-адрес и ключ потока.
   * **Кадр** - `Основной (16:9)` для обычной картинки, `Портретный (9:16)` для вертикального кадра.
   * **Энкодер** - общий с основным эфиром (по умолчанию, без дополнительной нагрузки) или
     отдельный. Пустые поля наследуют настройки основного эфира и показывают унаследованное значение.
   * **Параметры трансляции** - запускать/останавливать вместе с основным эфиром, задержка, попытки
     переподключения.
2. Нажми **Запустить** у потока или **Запустить все**.

Строка потока показывает состояние, время работы, битрейт отдачи, кадры в секунду и потерянные
кадры; панель инструментов суммирует, сколько потоков в эфире и какова общая отдача.

### Док `ManyCast Портрет`

Открывается в `Вид → Доки → ManyCast Портрет`.

1. Нажми **Из текущей сцены**, чтобы продублировать горизонтальную сцену (источники общие,
   преобразования независимы), или собери вертикальную раскладку с нуля через **Добавить источник**.
2. Расставь её в предпросмотре: перетаскивание - перемещение (с прилипанием к краям и центру
   кадра), угловая ручка - масштаб, `Ctrl`+колесо - изменение размера вокруг центра, двойной клик -
   свойства источника. **Вписать**, **Заполнить** и **По центру** помогут с первой расстановкой.
3. Список источников позволяет менять порядок, скрывать, блокировать и удалять элементы;
   **Размер кадра** переключает между 1080×1920, 720×1280, 1080×1080 и 1920×1080 (вертикальные
   трансляции нужно сначала остановить).

## 📱 Как вещать вертикальный кадр

| Платформа | Что нужно сделать |
|---|---|
| TikTok LIVE, Instagram, ... | добавить один поток с `Кадр: Портретный (9:16)` и ключом потока платформы |
| YouTube (горизонтальный + вертикальный) | включить **Dual stream** в комнате управления трансляцией, затем добавить поток со **вторым** ключом и `Кадр: Портретный (9:16)`; основной ключ остаётся в настройках трансляции самой OBS |
| Twitch (Dual Format) | OBS отправляет оба потока внутри одной сессии Enhanced Broadcasting: включи `Настройки → Вещание → Многодорожечное видео → Enhanced Broadcasting` и выбери `ManyCast Портрет` как **дополнительный кадр**. Не добавляй для вертикали отдельный поток Twitch - Twitch воспримет его как вторую независимую трансляцию |

> **Один ключ = одна трансляция.** Два потока нельзя отправлять на один ключ (второе подключение
> сбросит первое), поэтому вертикальному потоку нужен свой ключ на платформе.

## 🌍 Локализация

`data/locale` содержит английский, русский, немецкий, французский, итальянский, испанский и
упрощённый китайский. Чтобы добавить язык, скопируй `en-US.ini`, переведи значения, сохрани
подстановки `%1`/`%2` и держи каждое значение в кавычках - OBS обрезает значения без кавычек по
первому пробелу. Согласованность всех файлов проверяет `tests/check-locales.ps1` (он же запускается
в CI).

## ✅ Тестирование

```powershell
# из корня репозитория
$cmake = "{your_path}\cmake.exe"

# юнит-тесты (doctest) для кода без зависимостей от OBS
& $cmake --build --preset windows-x64 --config RelWithDebInfo --target manycast-tests
& ".\build_x64\tests\RelWithDebInfo\manycast-tests.exe"
& "{your_path}\ctest.exe" --test-dir build_x64 -C RelWithDebInfo --output-on-failure

# согласованность локалей (ключи, кавычки, подстановки)
powershell -ExecutionPolicy Bypass -File tests\check-locales.ps1

# собранная dll загружается, разрешает импорты и экспортирует API модуля OBS
powershell -ExecutionPolicy Bypass -File tests\smoke-plugin.ps1
```

Всё, что обращается к C API OBS (доки, выходы, энкодеры, кадры), можно проверить только внутри
OBS: смотри строки с префиксом `[manycast]` в `Справка → Файлы журнала → Посмотреть текущий журнал`.

## 🩺 Диагностика

| Симптом | Причина и решение |
|---|---|
| Док показывает `Офлайн`, и поток не запускается | энкодер основного эфира ещё не готов - запусти основной эфир хотя бы раз или включи у потока отдельный энкодер |
| `Не удалось создать сервис вещания...` или сервер отклонил ключ | неверная платформа, сервер или ключ; после включения YouTube dual stream скопируй **оба** ключа заново |
| Вертикальный предпросмотр остаётся чёрным | вертикальная сцена пуста - нажми `Из текущей сцены` или добавь источник |
| `Нельзя менять размер кадра, пока идут портретные трансляции` | останови вертикальные потоки, затем примени новый размер |
| После перезапуска у кадра не тот размер | OBS не хранит видеонастройки кадра; ManyCast пересоздаёт его и хранит размер в своём конфиге - задай его ещё раз в доке |
| Поток работает, но на платформе ничего нет | проверь, что оба потока не используют один и тот же ключ |
| В журнале ничего полезного | плагин пишет с префиксом `[manycast]` в `Справка → Файлы журнала → Посмотреть текущий журнал` |
